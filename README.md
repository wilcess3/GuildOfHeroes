#### Защита состояния

**1. Выбранное правило:**
Цена товара не может быть равна нулю или быть отрицательной. Магазин не может продавать товары бесплатно или работать в убыток
**2. Где оно проверяется:**

- В конструкторе: при создании объекта проверяется параметр price. Если он <= 0, срабатывает защита.
- В методе ApplyDiscount: при применении скидки проверяется, чтобы итоговая цена не ушла в минус (защита от скидки 100% и более)
- На уровне свойства: поле объявлено как public int Price { get; private set; }. Это запрещает любым внешним классам напрямую менять цену, минуя методы с проверками
- _Пример 1 (Конструктор):_ Входное значение price = -50. Фактическое значение после создания объекта: Price = 1 (сработала принудительная установка минимальной цены)
- _Пример 2 (Прямое присваивание):_ Попытка написать в Program.cs строку `eggs.Price = 999;. Фактический результат: **ошибка компиляции**

**Правило**: Цена товара (Price) не может быть отрицательной или равной нулю. Магазин не может продавать товары бесплатно или в убыток

Что сделано:

- Поле Price заменено на свойство public int Price { get; private set; }. Теперь напрямую изменить цену в Program.cs нельзя, только через методы класса

- Добавлен новый метод экземпляра ChangePrice(int newPrice). В нем реализована защита с ранним return: если новая цена <= 0, изменение отменяется

## (Практическая работа №2)

**Метод 1:** ApplyDiscount(int percent)
**Что делает:** Применяет скидку к товару. Изменяет текущую цену в зависимости от переданного процента. Имеет встроенную защиту: если попытаться передать скидку меньше 1% или больше 99%, метод выдаст ошибку и сработает ранний return, оставив цену без изменений

**Метод 2:** Sell(int amount)
**Что делает:** Уменьшает количество товара на складе. Проверяет, хватает ли товара, чтобы продать. Если на складе меньше, чем просят, выдает ошибку и не дает уйти в минус

**Метод 3:** CalculateTotalCost(int amountToBuy)
**Что возвращает:** Возвращает целое число — общую стоимость покупки. Результат вычисляется путем умножения текущей цены товара на количество, которое хочет купить покупатель

**Почему эти действия относятся именно к этому классу:**
Класс Product описывает реальный товар в магазине. В реальной жизни у товара есть несколько сценариев взаимодействия: на него могут действовать акции (скидки), его можно продать (уменьшение количества), и можно посчитать, сколько он стоит (расчет цены). Так как эти действия напрямую влияют на характеристики самого товара (его цену и количество), логично хранить методы, реализующие эти действия, прямо внутри класса Product
