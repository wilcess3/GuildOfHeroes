Свойства Price и Quantity объявлены как { get; private set; }. Это значит, что прочитать их может любой класс, но изменить их напрямую (присвоить значение) можно только изнутри класса Product

Свойство Name использует закрытое поле private string _name;. Это полное свойство, где в методе set происходит проверка на пустоту и обрезка лишних пробелов с помощью .Trim().

## (Практическая работа №2)

**Метод 1:** ApplyDiscount(int percent)
**Что делает:** Применяет скидку к товару. Изменяет текущую цену в зависимости от переданного процента. Имеет встроенную защиту: если попытаться передать скидку меньше 1% или больше 99%, метод выдаст ошибку и сработает ранний return, оставив цену без изменений

**Метод 2:** Sell(int amount)
**Что делает:** Уменьшает количество товара на складе. Проверяет, хватает ли товара, чтобы продать. Если на складе меньше, чем просят, выдает ошибку и не дает уйти в минус

**Метод 3:** CalculateTotalCost(int amountToBuy)
**Что возвращает:** Возвращает целое число — общую стоимость покупки. Результат вычисляется путем умножения текущей цены товара на количество, которое хочет купить покупатель

**Почему эти действия относятся именно к этому классу:**
Класс Product описывает реальный товар в магазине. В реальной жизни у товара есть несколько сценариев взаимодействия: на него могут действовать акции (скидки), его можно продать (уменьшение количества), и можно посчитать, сколько он стоит (расчет цены). Так как эти действия напрямую влияют на характеристики самого товара (его цену и количество), логично хранить методы, реализующие эти действия, прямо внутри класса Product

### Ответы на контрольные вопросы

1. **Чем отличается запрет внешней записи от проверки допустимого числа? Где проверяются здоровье при создании и его изменение?**

   * Запрет внешней записи на уровне компилятора запрещает любому коду извне (например, из Program.cs) напрямую менять значение поля. Выдается ошибка сборки
   * Проверка допустимого числа — это логические правила внутри самого класса. Если запись разрешена (внутри класса), проверка не даст записать некорректное значение (например, отрицательное)
   * Проверка здоровья при создании происходит в конструкторе (устанавливается MaxHealth, проверяется диапазон Health от 0 до MaxHealth). При изменении — внутри методов TakeDamage (проверка, что урон положительный, и что здоровье не падает ниже нуля) и Heal (проверка, что лечение положительное, и что здоровье не превышает MaxHealth)

2. **Как Name = name; связывает параметр конструктора, value и поле _name?**

   * В конструктор передается аргумент name. Строка Name = name;обращается к свойству Name. Так как конструктор находится внутри класса, он имеет доступ к private set
   * Внутри сеттера срабатывает невидимый параметр value, в который попадает значение из name 
   * Затем сеттер проверяет value на пустоту и обрезает пробелы, и только после этого сохраняет итоговый результат в скрытое поле _name

3. **Какие значения в проверках показали, что правило 0 <= Health <= MaxHealth соблюдается?**

   * При создании героя со здоровьем меньше нуля (например, new Hero("Тест", -5)), конструктор устанавливает Health = 0
   * Если передать здоровье больше максимума (например, new Hero("Тест", 999) при лимите 200), конструктор ограничивает Health = 200
   * В методе TakeDamage(200) при здоровье 75 здоровье становится 0 (а не -125). При лечении Heal(100) при здоровье 80 и максимуме 100, здоровье становится ровно 100


### Защита состояния Hero

1. **Почему методы ПР №2 не защищали от прямой записи в поле:**
Методы TakeDamage() и Heal() проверяли правила только в момент своего вызова. Однако поля оставались public, поэтому любой код Program.cs мог напрямую обойти методы и испортить состояние, например: yaroslav.Health = -5000

2. **Чем отличаются get, set и private set:**
* get — позволяет читать значение свойства из любого места программы.
* set — позволяет записывать значение свойства из любого места программы (делает свойство полностью открытым)
* private set — разрешает записывать значение только коду, который находится внутри того же класса (например, методам или конструктору)

3. **Где проверяется начальное здоровье:**
Начальное здоровье проверяется в конструкторе Hero(). Сначала задается и ограничивается рамками (от 1 до 200) значение MaxHealth. Затем проверяется Health: он не может быть меньше 0 и не может превышать MaxHealth

4. **Как Heal сохраняет границу MaxHealth:**
В методе Heal сначала считается нехватка здоровья (missingHealth = MaxHealth - Health). Если запрошенное лечение больше или равно этой нехватке, здоровье устанавливается ровно в MaxHealth. В противном случае лечение просто прибавляется к текущему здоровью

5. **Как Name использует поле \_name и значение value:**
Свойство Name работает с закрытым полем _name. При попытке присвоить имя, в невидимую переменную value попадает переданная строка. Внутри set значение value проверяется на пустоту и очищается от пробелов с помощью Trim(), и только потом сохраняется в _name

6. **Почему в конструкторе используется Name = name:**
Строка Name = name; обращается к свойству Name. Так как конструктор находится внутри класса Hero, он имеет доступ к private set. Это запускает все проверки (на пустоту и обрезку пробелов), написанные в сеттере. Если бы мы написали _name = name, проверки были бы обойдены.
